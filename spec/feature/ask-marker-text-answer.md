# ask マーカー質問へのテキスト回答

## SPEC-ASK-MARKER-TEXT-ANSWER: テキスト回答の記録

ask マーカー由来の質問カードは 3 経路から答えられる — Discord ボタン、WebUI、
そしてセッションへ届くテキスト返信。前 2 者は選択肢の index を持つが、テキスト返信は本文しか
持たない。従来はテキスト返信を検知すると **本文を捨てて** `pending-question/:id/resolve` を
呼んでいたため、次の問題が起きていた。

- カードは「回答済み」になるのに、回答内容がどこにも残らない。
- 先に resolve されるので、後から WebUI / ボタンで回答しても `already_answered` (409) で弾かれる。
- 質問と無関係なメッセージを 1 通投げただけでも、開いている質問が回答済みになる。

## 未回答の質問は blocker (2026-08-11 改訂)

「本文を回答として記録する」だけでは、**質問と無関係な発言 1 通でカードが閉じる**問題が残る。
さらに自動 inject (goal-and-go / お伺い / taskflow / Revisor 終局通知) も user フレームとして
戻ってくるため、**モデルが自分の質問に自分で答えて先へ進む**事故が起きていた。

そこで未回答の質問を blocker として扱う。

- カードが閉じるのは **明示回答** (`question.answered` = Discord ボタン / WebUI /
  `answer-question` API)、または文頭にコードを明示したテキスト返信のときだけ。
- それ以外のテキストはセッションに届くが**回答にはならない**。カードは開いたまま残り、
  後からボタン / WebUI でいつでも答えられる。
- 質問が開いている間、**自動 inject は pty に流さず保留**する
  ([askquestion-pending-gate.md](askquestion-pending-gate.md) の hold policy `"automatic"`)。
  人間の発言は保留しない — 会話まで止める必要は無い。
- 記録できなかった場合 (Concordia 不通、ボタン回答と競合して 409) は従来どおり resolve だけ通知し、
  古いボタンを失効させる。回答済みの質問を上書きしない。
- リモート回答 (`question.answered`) を受けた時点で、その質問は開いている集合から外す。
  注入された回答テキストが user フレームとして戻ってきても二重記録しない。

## 選択肢コード

- 質問カードの選択肢には `[A]` `[B]` … のコードを振る。ask リレー自体が壊れてカードを
  操作できないときの **避難口**として、テキストでも選択肢を指せるようにする。
- 回答と見なすのは **文頭にコードを明示した返信だけ** (`[A]` / `[a] でお願い` /
  `[A][C]` / `[A, C]`)。本文の途中に現れた `[B]` (ログや引用の貼り付け) は回答ではない。
- 複数選択の payload を使うのは、カード自身が `multiSelect` のときだけ。単一選択カードに
  複数コードが来たら最初の 1 つを採る。範囲外のコードは無視する。
- コードが無い返信は回答として記録しない (上記 blocker)。自由文で答えたいときは
  カードの「✏️ その他 (自由入力)」から送る。
